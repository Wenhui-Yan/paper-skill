# 多轮增量复查

## 继承问题，不继承判定

读取上轮报告和当前指定文件。按“文件角色 + Reviewer/Comment + 论点/原句锚点”匹配问题，沿用稳定 ID；不要靠变化后的行号匹配。没有历史材料就说明本轮是基线检查，不虚构已解决项。

每项旧问题在新版重查，并记录新证据：

- **已解决**：实际修正且相应跨文件位置同步；正文改对但回复仍旧，不能判全解决。
- **部分解决**：部分位置/子问题修正，明确剩余部分。
- **仍未解决**：当前证据确认问题仍存在。
- **新出现**：本轮新发现或修改引入；能证明回归才称回归，否则只称新发现。

当前材料不足以确认旧问题状态时写“本轮无法核实，保留上轮记录”，不要强行归入已解决或仍未解决。此项另用落实状态/确定性表达。

## 执行顺序

1. 记录文件版本和本轮范围；先复核旧 P1 及用户指出修改处。
2. 查其连带影响：删改导致的行号、图号、摘要/结论、回复引用句、SI 与 cover 总结。
3. 在用户所要求范围继续检查遗漏和新问题，不能把增量检查默认缩成只查用户承认的几处。
4. 已解决项放在“已修复”部分，保留证据而不重复要求修改。未解决项引用稳定 ID，说明仍差什么；同根问题合并，各受影响意见交叉引用。
5. 更新问题记录。正文内容变动完成后才统一校正最新印刷行号；已核实旧行号不能在新版本自动复用。

使用 assets/issue-ledger-template.md 保存可持续记录；没有必要历史时可在报告中保留简表，不额外生成空文件。
